AI BEGINNER ARTICLE

CodexでKindle本の公式HPを作り、GitHubに公開するまで。

コードが得意ではない人でも、AIに任せる順番を間違えなければ、企画、設計、実装、公開まで進められます。

今回作ったのは、Kindle本『Kindle出版始めたら6ヶ月でFIREできた私の話』の公式ミニHPです。単なるLPではなく、トップページ、本の紹介、著者紹介、読者特典、制作記事の5ページ構成にしました。

AI初心者にとって大事なのは、いきなり「おしゃれなサイトを作って」と頼まないことです。Codexには、素材を読み解く、構成を考える、実装する、確認して直す、公開する、という順番で任せると成果物が安定します。

1. なぜLPではなくHPにしたのか

LPは1ページで購入に誘導するには便利です。一方で、Codexの凄さを見せるなら、複数ページのHPの方が向いています。サイト構成、ページ間の導線、共通デザイン、スマホ対応、公開準備まで、AIに任せられる範囲が広くなるからです。

2. Codexに最初に渡した情報

まず本のWord原稿を素材として渡し、「この本をベースにHPを作り、GitHubに公開する制作過程をAI初心者向けの記事にしたい」と伝えました。ここで、目的と読者を先に伝えるのがポイントです。

3. 本の中身を読み解く

Codexに原稿から章立て、中心メッセージ、読者特典、著者プロフィールを抽出してもらいました。今回の中心テーマは「完全FIREではなく、会社に依存しない選択権を持つこと」です。

4. サイト構成を作る

構成は、ホーム、本の内容、著者、読者特典、制作記事の5ページにしました。初心者向けの記事としても説明しやすく、完成物としても公式サイトらしく見えるバランスです。

5. デザイン方針を決める

本のテーマは「焦り」から「選べる余裕」への変化です。そのため、強すぎる煽りではなく、落ち着いた紙のような背景、緑、金色、白を使い、信頼感と前向きさが出る見た目にしました。

6. 実装してもらう

GitHub Pagesで公開しやすいように、HTML、CSS、JavaScriptだけの静的サイトにしました。ビルド作業が不要なので、初心者でもファイルをアップするだけで公開しやすくなります。

7. スマホ表示を整える

本の読者はスマホで見る可能性が高いので、スマホ表示を重視しました。メニューは折りたたみ式にし、ボタンやカードが小さくなりすぎないように調整しています。

8. GitHubにアップする準備

プロジェクトには、公開用ファイル、画像、README、GitHub Pages用の設定ファイルを入れます。余計なビルド環境を使わないことで、初めてGitHubに触る人でも構造が理解しやすくなります。

9. GitHub Pagesで公開する

GitHubにリポジトリを作成し、ファイルをアップロードしたら、SettingsのPagesから公開元を選びます。今回は静的サイトなので、mainブランチのルートを公開元にすれば動きます。

10. 初心者がつまずきやすい点

よくあるつまずきは、画像パスの間違い、ファイル名の大文字小文字、GitHub Pagesの公開反映待ちです。Codexには「画面で崩れているところを直して」「GitHub Pagesで動くようにパスを確認して」と具体的に頼むと、修正が進みやすくなります。

実際に使いやすい依頼文

初心者の方は、次のように頼むと進めやすいです。

  • この本の原稿を読んで、公式HPに必要なページ構成を提案してください。
  • GitHub Pagesで公開できる静的サイトとして作ってください。
  • スマホでも読みやすいデザインにしてください。
  • 制作過程をAI初心者向けの記事として、10ステップでまとめてください。
  • 公開前にリンク切れ、画像表示、スマホ表示を確認してください。
